- [x] ClickHouse-backed tree queries still spend most of their frontend-shaped latency on avoidable round trips: `Tree.DirInfo` separately fetches the current summary, child list, and child summaries, while `Tree.Where` and `DirsHaveChildren` repeat the same children-then-summaries pattern during traversal. On the 1M-line `/lustre/scratch120/` subset this leaves current ClickHouse at about 20 ms for `tree_dirinfo`, 37 ms for `tree_disktree_endpoint`, and 229 ms for `tree_where`, versus master/Bolt at about 0.55 ms for `tree_dirinfo` and 45 ms for `tree_where`.

  - Preserved filter semantics by caching raw rows and applying filters at summary time; cloned cached slices and GUTAs on return so callers cannot mutate cached state.
  - Added regressions for repeated `Tree.DirInfo`, DiskTree-shaped `DirsHaveChildren`, repeated `Tree.Where`, caller mutation safety, and snapshot-id scoping.
  - Proved the fix on the same 1M-line `/lustre/scratch120/` subset with `repeat=20`, `warmup=2`: master/Bolt was `tree_dirinfo=0.552 ms`, `tree_where=45.203 ms`; pre-fix ClickHouse rerun was `tree_dirinfo=15 ms`, `tree_disktree_endpoint=27 ms`, `tree_where=186 ms`; cached ClickHouse was `tree_dirinfo=0 ms`, `tree_disktree_endpoint=0 ms`, `tree_where=4 ms`.
